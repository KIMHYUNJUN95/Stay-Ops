## 1. 영역 진입 · 레이아웃 껍데기

```
「운영 관리자」라는 제한된 영역의 진입 화면과 레이아웃 틀을 디자인해 주세요.

이 영역은 무엇인가:
숙박업 운영에서 **가격과 매출을 다루는 소수의 사무직**만 들어오는 곳입니다.
객실 가격을 바꾸고, 재고를 조정하고, 매출·가동률을 봅니다.
일반 현장 직원은 들어올 수 없고, 메뉴 자체가 보이지 않습니다.

필요한 것:

(1) 왼쪽 사이드바에 들어갈 메뉴 항목 하나
    - 기존 사이드바는 짙은 갈색이고 「운영 / 인력 / 정보」로 묶여 있습니다
    - 이 항목이 **특별한 영역**임이 드러나야 합니다(자물쇠 아이콘 등).
      다만 과하게 튀면 안 됩니다 — 같은 사이드바 안에 사는 항목입니다

(2) 영역에 들어왔을 때의 상단 틀
    - 영역 이름과 「제한된 영역」임을 알리는 표시
    - 4개 탭: 캘린더 / 가동률 / 매출 / 자동화
    - 탭은 기존 콘솔의 다른 화면들과 이질감이 없어야 합니다

(3) 각 탭의 빈 상태 (아직 내용이 없을 때)

(4) 권한이 없는 사람이 주소를 직접 입력해 들어왔을 때의 차단 화면
    - 겁주지 않되 분명해야 합니다. 「관리자에게 문의」 같은 다음 행동을 제시

주의:
· 이 영역에서 잘못 누르면 에어비앤비·부킹닷컴에 그대로 반영됩니다.
  「여기는 조심해야 하는 곳」이라는 느낌이 은은하게 있어야 하지만,
  매일 쓰는 화면이라 경고문으로 도배하면 안 됩니다.
```

## 2. 캘린더 — 격자 본체

```
숙박업 객실 가격 관리 캘린더의 메인 격자를 디자인해 주세요.
이 영역에서 가장 중요한 화면입니다. 여기서 매출을 만듭니다.

구조:
· 세로축 = 객실 (건물별로 묶임). 건물 9곳, 객실 총 90개.
  한 건물에 객실이 1개인 곳도 있고 26개인 곳도 있습니다.
· 가로축 = 날짜. 한 번에 한 달 정도가 보이고, 좌우로 움직일 수 있어야 합니다.
· 기간은 과거~미래 12개월 이상을 오갑니다.

한 칸(객실×날짜)에 담겨야 하는 정보:
  1) 가격 (예: ¥26,100) — 가장 중요. 한눈에 읽혀야 함
  2) 예약 막대 — 여러 날에 걸침. 채널별로 색이 다름
     (에어비앤비 / 부킹닷컴 / 직접예약)
  3) 최소 숙박일 (예: 2박) — 작게
  4) 차단(판매중지) 표시
  5) 저장 중인 값 — 서버 반영 전이라 「대기 중」으로 보여야 함

상호작용:
· 칸을 눌러 선택/해제 (여러 칸 선택 가능)
· 선택은 **객실 × 날짜 조합**이라 들쭉날쭉할 수 있습니다
  (201호의 20일 + 202호의 21일 같은 식)
· 선택된 칸이 몇 개인지 항상 보여야 합니다
· 선택한 뒤 「가격 수정」 등의 작업으로 넘어갑니다

윗부분에 필요한 것:
· 건물 선택 / 월 이동 / 오늘로 가기
· 선택 개수와 선택 해제
· 주요 작업 버튼들 (가격·재고·차단·예약생성)

주의:
· 90개 객실 × 30일 = 2,700칸이 될 수 있습니다. 밀도가 생명입니다
· 가격 숫자가 가장 잘 읽혀야 합니다
· 주말/오늘 열은 구분되어야 합니다
· 왼쪽 객실 이름과 위쪽 날짜는 스크롤해도 고정되어야 합니다
```

## 3. 캘린더 — 가격 수정 흐름

```
객실 가격을 한 번에 여러 칸 바꾸는 흐름을 디자인해 주세요.
이 영역에서 가장 자주 쓰는 기능이며, **틀리면 실제 판매가에 그대로 반영**됩니다.

3단계 흐름입니다.

[1단계] 무엇을 바꿀지
  · 건물 선택 → 객실 선택 (여러 개 / 전체)
  · 기간 선택 (달력 팝오버)
  · 요일 거르기 (예: 주말만, 평일만) ← 「다음 달 주말 전부」 같은 작업이 흔합니다

[2단계] 어떻게 바꿀지 — 두 가지 방식
  (A) 직접 입력: 금액을 적으면 선택한 칸 전부가 그 금액이 됨
  (B) 퍼센트: ±% 를 적으면 칸마다 현재가 기준으로 계산됨
      빠른 버튼: -20% -10% -5% +5% +10% +20% +30%
  ※ 퍼센트는 칸마다 결과 금액이 다릅니다

[3단계] 확인 — 가장 중요
  저장을 누르기 전에 무엇이 바뀌는지 숫자로 보여줘야 합니다:
    · 대상: 건물 · 객실 3개 · 기간 · 요일조건
    · 바뀌는 칸 수 (예: 42칸)
    · 이전 가격 → 새 가격
      (퍼센트일 때는 칸마다 다르므로 범위로: ¥23,400~31,200 → ¥28,000~37,400)
    · 이상한 값 경고: 0원, 평소의 1/10 이하, 10배 이상
      → 막지는 않되 눈에 띄게. 「그래도 저장」을 한 번 더 누르게
  버튼에 칸 수를 적어주세요: [ 42칸 저장 ]

주의:
· 사람이 이 화면에서 멈춰 서서 확인하게 만들어야 합니다.
  그렇다고 겁주는 빨간 화면은 아닙니다 — 매일 쓰는 기능입니다
· 3단계를 한 화면에 다 보여줄지, 단계별로 나눌지는 제안해 주세요.
  (참고: 기존 시스템은 2단계로 나뉘어 있었고, 확인 화면이 빈약했습니다)
· 에어비앤비 가격만 직접 정합니다. 부킹닷컴 가격은 시스템이 자동으로 맞추므로
  「참고」로만 보여주고 편집하지 않습니다
```

## 4. 캘린더 — 작업 진행 / 결과

```
가격 변경이 **즉시 반영되지 않고 순차 처리**되는데, 그 진행 상황을 보는 화면을 디자인해 주세요.

왜 즉시가 아닌가:
외부 예약 시스템(Beds24)에 분당 요청 제한이 있어서, 42칸을 바꾸면 몇 분에 걸쳐
순차적으로 전송됩니다. 사용자는 저장을 누른 즉시 화면을 떠날 수 있어야 합니다.

보여줘야 하는 상태:
  대기 중      아직 시작 안 됨
  처리 중      "18/42 완료" 같은 진행률
  완료         전부 성공
  일부 실패    ★ 중요 — 성공한 것과 실패한 것을 나눠서 보여줘야 함
               어느 객실·어느 날짜가 실패했는지, 다시 시도할 수 있게
  실패         전체 실패

필요한 것:
(1) 저장 직후 뜨는 알림 — 「접수되었습니다, 순차 처리 중」
(2) 진행 중인 작업 목록 (캘린더 화면 어딘가에 상주하거나 열어볼 수 있게)
(3) 작업 상세 — 무엇을 어떻게 바꾸는 중인지, 진행률, 실패 목록
(4) 캘린더 격자에서 「아직 반영 안 된 칸」 표시
    (새 가격을 미리 보여주되 확정이 아님이 드러나야 함)

주의:
· 「일부 실패」가 가장 위험한 상태입니다. 조용히 넘어가면 안 됩니다
· 사용자는 보통 저장하고 나가버립니다. 나중에 돌아왔을 때 결과를 알 수 있어야 합니다
```

## 5. 캘린더 — 재고·최소숙박·차단 / 수동 예약

```
가격 외의 캘린더 편집 기능들을 디자인해 주세요. 3번과 같은
「대상 선택 → 값 입력 → 확인」 흐름을 공유하되, 각각의 특성이 있습니다.

(1) 최소 숙박일
    · 선택한 칸의 최소/최대 숙박일 설정 (예: 최소 2박)
    · 성수기에 「3박 이상만」 같은 식으로 씁니다

(2) 재고
    · 판매 가능 수량 조정
    · 0으로 두면 사실상 판매 중지

(3) 차단 (판매 중지)
    · 기간을 골라 판매를 멈춤
    · 이미 걸린 차단을 푸는 기능도 필요
    · ★ 「시스템이 만든 차단」과 「사람이 만든 차단」을 구분해야 합니다.
      일괄 해제는 시스템이 만든 것만 지웁니다 — 사람이 의도해서 막은 것을
      실수로 풀면 안 됩니다

(4) 수동 예약 생성
    · 전화·지인 예약 등을 직접 입력
    · 필요한 것: 건물·객실·기간·투숙객 이름·인원·금액·메모
    · 이것은 외부 시스템에 **실제 예약을 만듭니다**. 확인 단계가 필요합니다

주의:
· 네 기능이 같은 껍데기를 공유하되 헷갈리지 않아야 합니다
· 지금 무엇을 편집 중인지 항상 분명해야 합니다
· 차단 해제는 되돌리기 어려우므로 확인을 받으세요
```

## 6. 매출 대시보드

```
숙박업 매출 대시보드를 디자인해 주세요.

기간을 골라(월/분기/임의 기간) 그 기간의 매출을 봅니다.
과거 데이터가 2022년부터 있어서 작년 대비 비교가 가능합니다.

핵심 지표 (카드로):
  매출          합계 금액
  ADR           평균 객실 단가 = 매출 ÷ **판매된** 객실박
  RevPAR        가용 객실당 매출 = 매출 ÷ **전체** 객실박
  점유율        판매 객실박 ÷ 전체 객실박
  객실당 매출
  ※ ADR 과 RevPAR 은 분모가 다릅니다. 헷갈리지 않게 보여주세요

필요한 화면 요소:
(1) 기간 선택 + 비교 기간 (작년 같은 기간 등)
(2) 지표 카드 — 전기 대비 증감 표시
(3) 추이 차트 — 일별/월별 매출
(4) 채널별 분해 — 에어비앤비 / 부킹닷컴 / 직접예약
    각각 매출·비중·수수료
(5) 건물별 표 — 건물 9곳의 매출·ADR·RevPAR·점유율
(6) 내보내기 버튼 (엑셀·PDF 한 쌍)

주의:
· 금액은 엔화(¥)이고 자릿수가 큽니다 (예: ¥12,345,678)
· 숫자 비교가 목적인 화면입니다. 차트보다 **표와 숫자가 주인공**입니다
· 데이터가 없는 기간이 있을 수 있습니다 (2022년 이전 등)
```

## 9. 자동화 상태

```
매일 자동으로 나가는 리포트들의 상태를 보는 화면을 디자인해 주세요.

무엇이 있나 (13종 정도):
· 슬랙으로 가는 일일 리포트 (매일 아침)
· 슬랙 알림 — 예약 취소, 당일 예약
· 노션 대시보드 동기화 (매일)
· 구글 시트 리포트
· 매출 스냅샷, 청소 인력 예측
각각 정해진 시각에 자동 실행됩니다.

필요한 것:
(1) 목록 — 이름 / 주기 / 마지막 실행 시각 / 결과(성공·실패) / 다음 예정
(2) 실패한 것 강조 — 「어제 슬랙 리포트가 안 갔다」를 바로 알 수 있어야 함
(3) 수동 실행 버튼 — 안 나갔을 때 다시 보내기
(4) 실행 이력 — 최근 며칠간의 성공/실패
(5) 발송 내용 미리보기 (어떤 메시지가 나가는지)

주의:
· 평소에는 아무도 안 보는 화면입니다. 문제가 생겼을 때만 봅니다
  → **문제가 있으면 목록 맨 위로 올라오거나 눈에 띄어야** 합니다
· 「마지막 실행이 언제였나」가 가장 중요한 정보입니다
· 수동 실행은 실제로 슬랙·노션에 발송됩니다. 실수로 누르면 안 됩니다
```

## 10. 취소 현황

```
취소 현황을 보는 화면을 디자인해 주세요.
※ 6번(매출)·7번(가동률)을 만든 뒤에 진행하세요. 단독 탭으로 둘지, 그 안의 섹션으로
   넣을지는 제안해 주세요.

왜 필요한가:
취소는 「안 팔렸다」가 아니라 **채널을 평가하는 지표**입니다.
실제 데이터(2022~2027, 15,400건):

  Booking.com   취소 2,700 / 유효 4,885 = 취소율 35.6%   예약 후 취소까지 17일
  Airbnb        취소 1,244 / 유효 6,010 = 취소율 17.1%   17일

부킹닷컴이 두 배입니다. 이걸 모르면 「예약이 많이 찼다」를 잘못 읽습니다.

보여줄 것:
1. 취소율 — 기간별 / 채널별 / 건물별
2. 취소된 금액 — 「이만큼 날아갔다」
   ⚠ 취소되면 외부 시스템이 금액을 0으로 비웁니다. 모르는 건을 0원으로 세지 말고
     「미상」으로 구분해야 합니다
3. 예약 → 취소까지 걸린 시간 (평균 17일)
4. 추이 — 취소율이 늘고 있는가
5. 취소 목록 — 언제·어느 방·어느 채널·얼마짜리

주의:
· 취소는 매출·가동률 계산에 들어가지 않습니다. 별도 지표입니다
· 취소율이 높은 것 자체는 나쁜 게 아닙니다(무료 취소 정책의 결과).
  단정하지 말고 **비교할 수 있게**만 보여주세요
· 취소 사유는 외부 시스템이 주지 않습니다. 사유별 분석은 불가능합니다
```

> **캘린더에도 반영이 필요합니다** — 2번 화면에 「취소된 예약 보기」 토글(기본 꺼짐).
> 켜면 취소 예약이 흐릿하게 같이 보입니다.
